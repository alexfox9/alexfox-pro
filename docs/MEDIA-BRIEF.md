## Capture guidance

- Send uncropped originals at original resolution, preferably Retina-quality PNG, so consistent crops can be chosen.
- Use a consistent theme/window size for primary screenshots. A second theme is useful when it explains a feature or design decision.
- Use fictional text such as “Review the draft on Friday”, “Thanks for your message”, and https://example.com/project. Match content across comparisons.
- Show enough real UI to identify History, Note, More, Tag, and Save. Avoid unrelated desktop windows.
- Optional demonstrations: MP4, one task per clip, around 8–15 seconds when practical, pointer visible, no private audio. Stills remain the default; autoplay is unnecessary.
- Never alter screenshots to imply nonexistent features. Use external captions/annotations to explain real actions.
- If an earlier version is unavailable, describe the earlier decision in text rather than inventing a before image.

## Research/evidence accompanying media

For each artifact, send: the problem, when it was made, your role, what changed next, and evidence for the decision. Explain whether it came from your observation/testing, interviews, surveys, competitive research, usage data, or another actual method. Keep qualitative results qualitative.

If using outcome numbers, include source, date range, definition, and limitations. Automated tests are not proof of improved usability.
